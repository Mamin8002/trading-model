# Граница LIVE: статус, гейт и что нужно для реального подключения биржи

Дата редакции: 2026-10-21 (крипторежим). Код: `src/tradebot/live/gate.py`,
`src/tradebot/exchange/base.py`, `src/tradebot/execution/interfaces.py`,
`src/tradebot/marketdata/interfaces.py`.

> **Главный факт: LIVE-торговля НЕДОСТУПНА.** Подключение к криптобирже не
> реализовано: в проекте нет API-клиента, сетевых запросов, аутентификации и
> отправки ордеров. Команда `live-preflight` всегда завершается отказом (код 2).
> Рабочий режим — TEST на локальных CSV ([simulation.md](simulation.md)).

---

## 1. Сводная таблица статусов

| Компонент | Статус | Где |
|---|---|---|
| Контракты рыночных данных (HistorySource, StreamSource, снимки) | реализованы как интерфейсы; биржевых реализаций нет | `marketdata/interfaces.py` |
| Контракт ордерного шлюза (BrokerGateway) | реализован как интерфейс; реализаций нет | `execution/interfaces.py` |
| Точка подключения биржи (ExchangeAdapter) | контракт + явный статус «не реализовано» | `exchange/base.py` |
| Многофакторный LIVE-гейт | реализован, проверен тестами; **всегда отказывает** (условие №0) | `live/gate.py` |
| API-клиент биржи / аутентификация / ордера | **НЕ реализованы** | — |
| LIVE-оркестратор (потоки, BarFinalizer, reconciliation-цикл) | **НЕ реализован** | roadmap E3 |
| TEST-симулятор | реализован, проверен офлайн | `execution/simulator.py` |

Ничего из этого не является production-ready для торговли; статусы обновляются
только вместе с кодом и проверками.

## 2. Режимы по умолчанию

- `run.mode: TEST` — единственный работающий режим; команда `test` отклоняет
  конфиг с `mode: LIVE` (код 2);
- секция `live` по умолчанию отсутствует; `live.allow_orders: false` — дефолт схемы;
- kill-switch-файл (`.kill`) блокирует заявки, даже если всё остальное включено;
- переменная окружения `TRADEBOT_LIVE_ACK` без значения-подтверждения — гейт не проходит.

## 3. Многофакторный LIVE-гейт (`live/gate.py`)

Для разрешения ордерного контура (в будущем) требуется ОДНОВРЕМЕННО:

0. **реализованная интеграция с биржей** — `exchange.base.EXCHANGE_INTEGRATION_AVAILABLE == True`.
   Сейчас константа равна `False`, поэтому гейт НЕ ПРОХОДИТ НИ ПРИ КАКИХ других
   условиях. Это явная блокировка: переключение константы допустимо только
   вместе с реальной проверенной реализацией адаптера;
1. `run.mode: LIVE` в отдельной конфигурации;
2. явный флаг CLI `--allow-live`;
3. переменная окружения `TRADEBOT_LIVE_ACK` == `live.ack_expected_value`;
4. секция `live` с `allow_orders: true`;
5. `live.max_order_quantity_units` задан явно;
6. подтверждённые параметры инструмента (`instrument.price_step`, `instrument.lot_size_units`);
7. полный risk-конфиг (как для симулятора);
8. отсутствие kill-switch-файла.

Гейт — чистая функция: отказ происходит ДО любых сетевых вызовов (которых в
проекте сейчас вообще нет). Результат содержит полный список нарушений.

```powershell
# поведение команды сегодня — всегда отказ с перечнем причин:
python -m tradebot live-preflight --config configs\demo.yaml --allow-live
# exit code 2; stderr: «LIVE-гейт НЕ пройден … интеграция с криптобиржей НЕ реализована»
```

## 4. Контракты будущего биржевого адаптера

Реализация адаптера (когда она появится) обязана:

- **рыночные данные**: реализовать порты `marketdata` (история, снимки, потоки);
  поток обязан учитывать мутацию незакрытой свечи (BarFinalizer, `is_final`),
  дедупликацию по (symbol, tf, ts_open) и сверку после обрывов соединения;
- **исполнение**: реализовать `execution.BrokerGateway` — детерминированный
  `client_order_id` (защита от дублей), потерянный ответ → `UNKNOWN_RESULT` +
  `resolve_unknown()` вместо слепого повтора, `reconcile_positions()` против
  локального учёта, rate-limit дисциплина биржи;
- **безопасность**: ключи API — только из окружения (`config/env.py`),
  маскирование в логах/журнале; kill-switch; лимиты RiskGuards до шлюза;
- **типы рынка**: явно зафиксировать спот/маржу/фьючерсы, дробные количества
  (decisions D14/D15) — сейчас они НЕ предполагаются.

## 5. Что осталось до реального LIVE (чек-лист, roadmap E1–E3)

1. **E1 — исследование биржи**: документация REST/WS, лимиты, семантика меток
   свечей, формат ошибок, спецификации пар (tickSize/stepSize), тестнет.
2. **E2 — read-only адаптер рыночных данных**: реализация HistorySource/
   StreamSource + контрактные тесты; сверка с локальными CSV; BarFinalizer.
3. **E3 — ордерный шлюз и LIVE-оркестратор**: BrokerGateway за гейтом,
   reconciliation-цикл, алерты, проверка на тестнете/минимальных объёмах;
   переключение `EXCHANGE_INTEGRATION_AVAILABLE` — только после всех проверок.
4. Отдельное осознанное решение о реальных ордерах (P9) — вне рамок текущего кода.

## 6. Гарантии текущего состояния

- в кодовой базе отсутствуют сетевые вызовы и торговые эндпоинты (гигиенические
  тесты `tests/test_env_cli.py` блокируют их появление);
- `python -m tradebot test` физически не может отправить заявку: исполнение
  только в `SimulatedBroker` по историческим барам;
- отчёты и журнал содержат дисклеймер «Реальные заявки не выставлялись»;
- проект не обещает доходность; все торговые цифры — диагностические (decisions D16).
