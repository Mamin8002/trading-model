*Версия документа: 2026-10-22. Соответствует состоянию проекта после Этапа 4.*

---

## 1. Что это за бот — и чем он НЕ является

**Бот делает:**
- получает публичные рыночные данные Bybit (BTCUSDT Spot по умолчанию): цену в реальном
  времени, историю 5-минутных свечей;
- после закрытия каждой свечи формирует сигнал **BUY / SELL / HOLD** с уровнем уверенности,
  временем, ценой, инструментом и версией модели;
- показывает консольный дашборд: цена, свечи, состояние соединения, свежесть данных,
  сигналы, открытые позиции и рекомендации по их сопровождению;
- ведёт журнал всех сигналов и **вручную зарегистрированных** позиций (вход, частичное и
  полное закрытие, результат), переживающий перезапуск.

**Бот НЕ делает:**
- не размещает/изменяет/отменяет ордера, не использует приватные API, не запрашивает
  баланс, не требует и не хранит API-ключи (только публичные read-only данные);
- не знает, исполнили ли вы сигнал, — пока вы не зарегистрируете вход вручную;
- не изобретает уровни стоп-лосса/тейк-профита/срока удержания — используются только
  явно заданные вами правила;
- не переобучает модель автоматически на результатах ваших позиций.

> **Дисклеймер.** Сигналы — вывод статистической модели. Это не гарантия дохода и не
> персональная финансовая рекомендация. Валидация показала statistically значимое, но
> малое преимущество над случайным уровнем (~50.6% против ~49.8%), которое **не покрывает
> комиссии биржи** на 5-минутном горизонте (подробности — раздел 10 и `docs/validation_report.md`).

## 3. Быстрый старт (первый запуск за ~5 минут)

```powershell
# 1. Скачать историю BTCUSDT (публичный REST Bybit, ~2-3 мин, ~296 запросов)
python scripts\download_history.py

# 2. Обучить модель + walk-forward-валидация (офлайн, ~35 с)
python scripts\train_model.py

# 3. Демо без сети: реплей последних 40 баров
python scripts\run_bot.py --mode TEST --replay-bars 40 --speed 4

# 4. Живой мониторинг (Ctrl+C для выхода)
python scripts\run_bot.py --mode LIVE
```

После шага 4 дашборд сразу покажет ~300 последних свечей (разовая REST-догрузка) и текущую
цену; первый сигнал появится после закрытия ближайшей 5-минутной свечи (ждать до 5 минут).

## 4. Конфигурация — `config/default.yaml`

### 4.1. Режим и инструмент

```yaml
mode: TEST            # TEST (офлайн) или LIVE (WebSocket Bybit); run_bot.py --mode переопределяет
exchange:
  category: spot      # spot | linear | inverse
  symbol: BTCUSDT     # любой инструмент Bybit, UPPERCASE (например ETHUSDT)
  interval: "5"       # 1,3,5,15,30,60,120,240,360,720,D,W,M
```

Смена инструмента/интервала: измените конфиг → заново `download_history.py` →
`train_model.py` (модель привязана к инструменту и интервалу; бот отклонит чужой артефакт).

### 4.2. Горизонт прогноза (ваша настройка «на сколько вперёд смотреть»)

```yaml
model:
  horizon_bars: 1     # 1 бар = 5 минут; 12 баров = 1 час; 288 баров = сутки
```

После изменения **обязательно** переобучите модель (`python scripts\train_model.py`) —
версия артефакта включает горизонт (`...-h12-...`), и predictor не даст запустить бота
при рассогласовании конфига и модели. Чем больше горизонт, тем реже переобучение теряет
актуальность, но и тем «шумнее» целевая переменная.

### 4.3. Уверенность и воздержание

```yaml
model:
  confidence_threshold: 0.55   # уверенность = max(prob up, prob down); ниже порога -> HOLD
```

- `0.55` (по умолчанию): ~20% баров получают BUY/SELL, точность на них ~51.4% (валидация).
- выше (например `0.60`): реже сигналы, формально выше точность на покрытии, но меньше действий;
- `0.51`: почти на каждый бар BUY/SELL, но качество близко к подбрасыванию монеты.

### 4.4. Условия выхода (для сопровождения позиций)

```yaml
positions:
  exit_rules:
    take_profit_pct: null   # например 1.5  -> +1.5% от цены входа = рекомендация закрыть
    stop_loss_pct: null     # например 1.0  -> -1.0% от цены входа
    max_hold_bars: null     # например 12   -> 12 баров (60 мин) от момента входа
  allow_short: false        # не меняется: spot-бот шорты не поддерживает
```

По умолчанию правила **не заданы** (null) — это осознанно: бот ничего не выдумывает.
Пока правил нет:
- сигналы BUY фиксируются, но **рекомендация на вход воздерживается** (в дашборде и
  журнале будет `ВХОД_ВОЗДЕРЖАНИЕ` с подсказкой настроить правила);
- сопровождение открытой позиции опирается только на встречные сигналы модели.

Правила можно задать и **для конкретной позиции** при регистрации (`--tp/--sl/--max-hold`) —
они приоритетнее конфига.

### 4.5. Свежесть данных и журнал

```yaml
signals:
  stale_after_intervals: 3   # нет данных 3*5=15 минут -> STALE, сигналы помечаются неактуальными
journal:
  path: data/journal/journal.json   # LIVE-журнал; TEST-реплей по умолчанию пишет journal_test.json
```

## 5. Данные: загрузка и качество

```powershell
python scripts\download_history.py                          # от data.history_start (2024-01-01) до сейчас
python scripts\download_history.py --start 2025-01-01       # свой период
python scripts\download_history.py --end 2026-06-30         # период с концом
```

Создаваемые файлы:
- `data\raw\bybit_spot_BTCUSDT_5m_<период>_fetched<UTC>.csv` — сырые свечи
  (`start_ms,time_utc,open,high,low,close,volume,turnover,is_closed`);
- `.csv.metadata.json` — инструмент, категория, интервал, период, дата загрузки, эндпоинт;
- `data\processed\...clean.csv` — очищенные закрытые бары;
- `data\processed\...clean.report.json` — отчёт: дубликаты, некорректные строки,
  незакрытые свечи, диапазоны пропусков.

Гарантии обработки: дедупликация по времени, строгая хронология, исключение незакрытой
свечи, пропуски **детектируются, но не заполняются** (ничего не фабрикуется). Для
BTCUSDT 5m пропусков на Bybit практически нет (проверено на 295 тыс. баров).

Лимиты Bybit: 600 запросов/5 с на IP (403 → бан ~10 мин). Загрузчик троттлит до ~3 req/s
и ретраит с backoff — при обычной работе лимиты недостижимы.

## 6. Модель: обучение, артефакт, переобучение

```powershell
python scripts\train_model.py                     # полный прогон: оба варианта признаков, 8 окон валидации
python scripts\train_model.py --quick             # смоук (3 окна, 40k баров)
python scripts\train_model.py --feature-set ratio # зафиксировать набор признаков
python scripts\train_model.py --folds 12          # больше окон валидации
```

Результаты:
- `data\models\<model_version>\model.joblib` — модель;
- `model_card.json` — версия, инструмент, интервал, горизонт, признаки, параметры,
  период обучения, метрики walk-forward, версии библиотек, ограничения;
- `walk_forward.json` — полная детализация по окнам;
- `docs\validation_report.md` — человекочитаемый отчёт (переписывается каждым запуском).

Версия модели выглядит как `xgb-BTCUSDT-spot-5m-h1-ratio-20261021T192859Z` и видна в
дашборде, в каждом сигнале и в журнале. Бот автоматически берёт **последний** артефакт из
`data\models\` (переопределение: `--model-dir` у `run_bot.py` или `model.artifact_dir` в конфиге).

**Когда переобучать:** модель стареет вместе с рынком. Практические ориентиры —
раз в 1–3 месяца, после сильных смен режима цены, и обязательно при смене
`horizon_bars`/`symbol`/`interval`. Переобучение — только вручную, `train_model.py`;
по результатам ваших позиций модель автоматически не переобучается (осознанное ограничение).

**Как читать качество:** ключевая строка отчёта — сравнение walk-forward accuracy с
majority-baseline по окнам. Если accuracy модели систематически сравнивается с baseline —
модель потеряла преимущество; торговать ею нельзя (см. раздел 10).

## 7. Мониторинг: LIVE и TEST

### 7.1. LIVE

```powershell
python scripts\run_bot.py --mode LIVE                  # до Ctrl+C
python scripts\run_bot.py --mode LIVE --duration 660   # автономно 11 минут и выход
python scripts\run_bot.py --mode LIVE --line-ui        # построчный вывод вместо перерисовки
```

Что происходит при старте: подключение к `wss://stream.bybit.com/v5/public/spot` →
подписка на `kline.5.BTCUSDT` и `tickers.BTCUSDT` → разовая REST-догрузка ~300 последних
свечей для истории на экране (**сигналы по ним не выдаются**).

### 7.2. Как читать дашборд

```
==============================================================================
 BTC MONITOR | Bybit public data | режим LIVE
 spot/BTCUSDT  interval 5m  |  модель xgb-...-h1-ratio-... (горизонт 5 мин, порог 0.55)
==============================================================================
 Соединение: CONNECTED (подписка подтверждена)  | переподключений: 0
 Данные: FRESH (последнее обновление 0 с назад, порог 900 с) | серверное время: 19:28:15 UTC
 Цена: 84,456.70 USDT (ticker, 0 с назад)
------------------------------------------------------------------------------
 Формирующаяся свеча 19:25:00 UTC: O ... (сигнал ТОЛЬКО после закрытия)
 Последние закрытые свечи (UTC, всего в памяти 300): ...
------------------------------------------------------------------------------
 ТЕКУЩИЙ СИГНАЛ (бар 19:20:00 -> 19:25:00 UTC):
   >>> BUY <<<  уверенность 0.582  выдан 2026-10-21 19:25:01 UTC
   инструмент spot/BTCUSDT  цена на момент выдачи 84,456.70 (ticker)  горизонт 5 мин
   версия модели xgb-...  | данные FRESH
   причина: ... (появляется при HOLD/проблемах с данными)
------------------------------------------------------------------------------
 История сигналов (последние 5)
------------------------------------------------------------------------------
 Журнал: data/journal/journal.json | сигналов: N, позиций: M (открыто ..., PnL ...)
 Позиции: ... (блок открытых позиций с условиями выхода и исходным сигналом)
 Рекомендация [ДЕРЖАТЬ/РАССМОТРЕТЬ_ЗАКРЫТИЕ/...] (по сигналу sig-NNNNNN): ...
==============================================================================
 Сигналы - вывод модели, не гарантия дохода и не персональная финансовая рекомендация.
```

Ключевые состояния:
- **Соединение**: `CONNECTED` → норма; `RECONNECTING (попытка N)` → обрыв, бот сам
  переподключается (backoff 1→60 с) и догружает пропущенные свечи через REST;
- **Данные**: `FRESH` → обновления моложе 15 мин (3×интервал); `STALE` → новых данных нет,
  **новые сигналы не выдаются как актуальные**, рекомендации по позициям не выдаются;
- **Сигнал `данные НЕ АКТУАЛЬНЫ`** → у сигнала перечислены причины (устаревший бар,
  разрыв истории, устаревший поток). Такой сигнал записывается в журнал, но полагаться
  на него нельзя;
- **HOLD** — штатное воздержание модели (уверенность < порога). На 5-минутном горизонте
  это большинство баров (~80% при пороге 0.55) — так и задумано.

### 7.3. TEST (без сети)

```powershell
python scripts\run_bot.py --mode TEST --replay-bars 40 --speed 4
python scripts\run_bot.py --mode TEST --replay-bars 120 --speed 0 --line-ui   # мгновенно
python scripts\run_bot.py --mode TEST --replay-file data\processed\<файл>.clean.csv
```

Реплей проигрывает сохранённые свечи через тот же тракт (включая формирующиеся свечи и

актуальны). Журнал TEST по умолчанию отдельный: `data\journal\journal_test.json`
(переопределение `--journal PATH`).

## 8. Позиции: ручная регистрация и сопровождение

### 8.1. Принципы

1. **Сигналы и позиции разделены.** Без приватного API бот не знает, исполнили ли вы
   сигнал и по какой цене. Сигнал становится «исполненным» только после ручной
   регистрации входа.
2. **SELL для spot BTCUSDT = закрыть/уменьшить длинную позицию.** Шорт не открывается;
   регистрация SHORT отклоняется.
3. Если пришёл SELL, а зарегистрированной позиции нет, бот сообщает: **«фактическое
   состояние портфеля неизвестно»** — и не утверждает, что нужно что-то закрывать.
4. Все действия фиксируются в журнале: сигнал с ценой на момент выдачи, подтверждение
   входа, каждое закрытие (частичное/полное), причины смены статуса, итоговый результат.

### 8.2. Команды `position_cli.py`

Флаг `--journal PATH` указывает файл журнала (по умолчанию из конфига). Все команды офлайн.

```powershell
# посмотреть последние сигналы (ID needed для привязки входа)
python scripts\position_cli.py signals --last 20

# зарегистрировать фактический вход:
#   --price/--quantity  фактические цена и объём вашей сделки
#   --time              UTC время входа "YYYY-MM-DD HH:MM[:SS]" (по умолчанию - сейчас)
#   --signal-id         привязка к сигналу (рекомендуется; сигнал помечается подтверждённым)
#   --tp/--sl/--max-hold  условия выхода для этой позиции (приоритетнее конфига)
python scripts\position_cli.py register-entry --price 84500 --quantity 0.01 --signal-id sig-000123 --tp 1.5 --sl 1.0 --max-hold 12 --time "2026-10-22 10:15"

# частичное закрытие
python scripts\position_cli.py close --position-id pos-000001 --price 85000 --quantity 0.004

# полное закрытие остатка (без --quantity)
python scripts\position_cli.py close --position-id pos-000001 --price 84800

# списки/детали/статистика/события
python scripts\position_cli.py list          # открытые
python scripts\position_cli.py list --all    # включая закрытые
python scripts\position_cli.py show --position-id pos-000001   # полный JSON: fills, status_history, source_signal
python scripts\position_cli.py stats         # сигналы/позиции/PnL по ручным данным
python scripts\position_cli.py events --last 20
```

PnL считается только по введённым вами данным: средневзвешенная цена выхода,
`realized_pnl_quote` (USDT) и `%` от закрытой ноты, исход WIN/LOSS/FLAT.

### 8.3. Логика рекомендаций советника

| Состояние | Новый сигнал | Рекомендация бота |
|---|---|---|
| Позиция открыта | BUY (в направлении позиции) | **ДЕРЖАТЬ** (условия выхода не сработали) |
| Позиция открыта | SELL (встречный) | **РАССМОТРЕТЬ ЗАКРЫТИЕ** + причина: встречный сигнал модели (уверенность, время) и/или сработавшие настроенные условия |
| Позиция открыта | HOLD | **НАБЛЮДАТЬ** |
| Позиция открыта | любой, но сработало TP/SL/max_hold | **РАССМОТРЕТЬ ЗАКРЫТИЕ** + какое именно правило сработало (с уровнями и числами) |
| Позиция открыта | сигнал на устаревших данных | рекомендаций НЕТ (`данные устарели`) |
| Позиции нет | BUY, правила выхода заданы | **ВХОД ВОЗМОЖЕН** (с напоминанием: исполнение — только вручную, сигнал не считается исполненным) |
| Позиции нет | BUY, правила НЕ заданы | **ВХОД ВОЗДЕРЖАНИЕ** («настройте условия выхода») |
| Позиции нет | SELL | **ПОРТФЕЛЬ НЕИЗВЕСТЕН** (шорт не открывается) |
| Позиции нет | HOLD | **НАБЛЮДАТЬ** |

Рекомендация — не приказ: исполнение всегда вручную. Каждая рекомендация записывается в
event-log журнала (`advice_issued`) с привязкой к сигналу.

Советник учитывает историю сигналов: повторяющиеся подряд сигналы отмечаются в причинах
(«это 3-й подряд сигнал BUY»).

### 8.4. Персистентность

Журнал — обычный JSON (`data\journal\journal.json`), пишется атомарно после каждого
действия. Переживает перезапуск бота и машины. Если файл повреждён, бот **не**
перезаписывает его молча, а сообщает об ошибке — восстановите файл вручную (можно из
резервной копии; рекомендуется периодически копировать журнал).

| Accuracy majority-baseline | 0.4981 |
| Accuracy momentum-baseline | 0.4894 |
| Accuracy при уверенности ≥ 0.55 (покрытие 21.3%) | 0.5142 |
| Среднее абсолютное движение бара | ≈ 0.094% |
| Ожидаемый валовой выигрыш на сигнал ≈ (2·acc−1)·Eabs(Δ) | **≈ 0.001%** |
| Комиссия spot round-trip (taker ~0.1%×2) | ≈ 0.2% |

Выводы:
- преимущество над baseline статистически заметно (~5σ при n=118k), но на **два порядка
  меньше комиссий** — как торговый алгоритм на 5-минутном горизонте модель непригодна;
  это исследовательский монитор направления;
- accuracy ≠ прибыльность; спред, комиссии, слиппедж в метриках не учтены;
- исходная модель из репозитория Sumit2514 невоспроизводима (данные автора отсутствуют) —
  заявленные там метрики непроверяемы; наш перенос подхода даёт честные ~50–51%;
- качество зависит от рыночного режима; при деградации (accuracy ≈ baseline в последних
  окнах отчёта) используйте только HOLD-режим наблюдения и переобучите модель;
- смена `horizon_bars` может как улучшить, так и ухудшить результат — проверяйте
  walk-forward-отчётом после каждого переобучения.

## 11. Повседневное использование (рекомендуемый цикл)

1. **Ежедневно/по желанию:** `run_bot.py --mode LIVE` — наблюдение; интересны только
   сигналы с `данные FRESH` и уверенностью заметно выше порога.
2. **При исполнении сделки:** сразу `position_cli.py register-entry ...` с фактической
   ценой/временем/объёмом и (желательно) условиями выхода.
3. **При закрытии:** `position_cli.py close ...` (частично или полностью).
4. **Раз в 1–3 месяца:** `download_history.py` → `train_model.py` → сравнить метрики в
   `docs\validation_report.md` с предыдущими; если качество упало до baseline —
   воздержитесь от использования сигналов.
5. **Резервная копия:** периодически копируйте `data\journal\journal.json`.

## 12. Решение проблем

| Симптом | Причина / действие |
|---|---|
| `UserWarning ... serialized model ... XGBoost` при старте | Артефакт сохранён другой версией XGBoost. Безвредно; уберётся после локального `train_model.py` |
| `Артефакт модели не найден` | Не обучали модель или очистили `data\models` → `python scripts\train_model.py` |
| `Артефакт модели не соответствует конфигурации` | Изменили symbol/interval/horizon без переобучения → `train_model.py` (или верните конфиг) |
| `Clean-данные не найдены` (train/replay) | Не скачана история → `python scripts\download_history.py` |
| HTTP 403 от Bybit при загрузке | Превышен IP-лимит; подождите ~10 минут, повторите |
| `RECONNECTING` в дашборде | Обрыв сети/прокси; бот переподключится сам и догрузит пропущенные свечи; сигналы в этот период помечаются неактуальными |
| `STALE` длительное время | Нет обновлений >15 мин: проверьте сеть/региональную доступность `stream.bybit.com` |
| Дашборд «множится» в терминале | Копируется scrollback Windows Terminal — на экране одна панель; при проблемах с ANSI используйте `--line-ui` |
| `Журнал ... повреждён` | Файл журнала не перезаписывается молча; восстановите из копии или переместите повреждённый файл и создайте новый |
| Время на машине спешит/отстаёт | Бот использует серверное время Bybit для данных; drift до 2 мин ни на что не влияет |

- Секретов нет нигде: бот использует только публичные эндпоинты; в коде, конфигах,
  журналах и проверках отсутствуют API-ключи и торговые вызовы (это подтверждается
  структурным сканом в `check_stage3_stream.py` A9 и `check_stage4_positions.py` A11).
- Компоненты Finam/MOEX в проекте отсутствуют (проект создан с нуля; удалять было нечего).
- Данные журнала — локальные; не публикуйте их, если не хотите раскрывать свои сделки.

## 15. FAQ

**Почему почти все сигналы HOLD?**
Модель честно воздерживается, когда уверенность ниже порога (0.55). На эффективном
5-минутном горизонте так и должно быть: действий мало, и они слабые (раздел 10).

**Сигналы пропадают после перезапуска?**
Список «последних сигналов» в дашборде — оперативная память. Полная история — в
`data\journal\journal.json` (`position_cli.py signals/events`) и переживает перезапуск.

**Можно ли торговать по этим сигналам автоматически?**
Нет. Бот не имеет торговых API по замыслу (безопасность), а экономическое преимущество
модели не покрывает комиссии (раздел 10).

**Как узнать, какая модель сейчас работает?**
Версия видна в шапке дашборда, в каждом сигнале и в `data\models\<version>\model_card.json`.

**Бот видит мои сделки на Bybit?**
Нет. Только то, что вы зарегистрировали вручную через `position_cli.py`.

**Что значит «данные НЕ АКТУАЛЬНЫ» у сигнала?**
Сигнал сформирован по устаревшему/неполному бару (обрыв соединения, поздняя догрузка).
Он сохранён для истории, но действовать по нему не следует.
