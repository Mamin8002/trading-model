# Roadmap: этапы реализации (крипторежим)

Дата редакции: 2026-10-21. Каждый этап — небольшой, с проверяемым результатом
(критерии приёмки), файлами и рисками. Этап считается принятым, только если
выполнены ВСЕ критерии приёмки.

Ссылки: модули — [architecture.md](architecture.md), обоснования —
[decisions.md](decisions.md), LIVE-граница — [live.md](live.md).

Обозначения блоков: **D** — данные, **F** — признаки, **M** — ML,
**B** — бэктест/риск, **T** — TEST-пайплайн, **E** — биржа/LIVE (будущее).

---

## Выполнено (проверено офлайн-сценариями и тестами)

### Каркас и конфигурация
- структура проекта, строгая pydantic-схема (extra=forbid), YAML-конфиги, хэш конфига;
- инфраструктура секретов (env/.env, маскирование) — сейчас не задействована (сети нет).

### D1–D2. Слой данных
- контракт `Bar` (UTC, bar_open, дробный volume — decisions D13);
- CSV-загрузчик + валидатор (ошибки/предупреждения, ничего не чинится молча);
- ресэмплинг 1m/5m → 5m/10m/15m/1h: только полные интервалы, pending-хвост, календарь покрытия;
- календарь сессий + режим 24/7 (`always_on_calendar`, окна 00:00–24:00) — крипторынок;
- синтетический генератор демо-данных (seed-воспроизводимый, continuous 24/7);
- CLI `validate_data`.
- Приёмка: `scripts/manual_checks/check_phase_02_data.py` — PASS.

### F1–F2, M1–M2. Признаки и ML
- 31 причинный признак v1 + манифест; тесты причинности (префикс-инвариантность, возмущение будущего);
- метки forward-return с нейтральной полосой (классификация/регрессия);
- purged walk-forward сплиты с embargo; leakage-аудит (random vs walk-forward);
- LightGBM + базейны (majority/momentum/logreg), детерминированность (seed);
- реестр моделей (артефакт + метаданные + манифест признаков), отчёты;
- CLI `train`. Приёмка: `check_phase_03_ml.py` — PASS.

### B1. Риск-контроль и TEST-симулятор
- RiskGuards: лимиты позиции/капитала/заявок в день/дневного убытка/просадки/свежести данных; halt-логика;
- sizing (фиксированный и рисковый от стопа), проверки price_step/lot_size;
- EventSimulator: исполнение на open следующего бара, слиппедж/комиссия (явные), стоп/цель, консервативное правило конфликта stop_first;
- JSONL-журнал решений/исполнений + отчёты; CLI `simulate`.
- Приёмка: `check_phase_04_simulation.py` — PASS.

### T1. Единый TEST-пайплайн и LIVE-гейт
- `python -m tradebot test` (данные → модель → симуляция → отчёт/журнал), коды возврата;
- многофакторный LIVE-гейт (`live/gate.py`), kill-switch.
- Приёмка: `check_phase_05_test_run.py` — PASS.

### C1. Перевод в крипторежим (текущая редакция)
- удалена прежняя брокерская интеграция (пакет адаптера, read-only CLI, секция конфига,
  зависимости не потребовались — сетевых библиотек не было); формат `ticker@mic` заменён
  тикером пары (D12);
- время: UTC по умолчанию, календарь 24/7, `trading_days_per_year: 365`, дробный volume (D11, D13);
- точка подключения биржи `exchange/` (контракт + статус «не реализовано»); LIVE-гейт
  дополнен условием №0 — сейчас LIVE заблокирован всегда (D8);
- рынок не предполагается: спот/маржа/фьючерсы — отложенные решения (D15, D14);
- конфиги/демо-данные/документация переведены на криптопримеры;
- приёмка: `scripts/manual_checks/check_crypto_mode.py` — PASS (офлайн).

## Далее (НЕ реализовано; каждый этап — отдельная задача с приёмкой)

### E1. Исследование целевой криптобиржи
- **Цель**: выбрать биржу (P6) и задокументировать: REST/WS-эндпоинты свечей/стакана/аккаунта,
  аутентификацию и лимиты запросов, семантику меток свечей (bar_open/bar_close!),
  спецификации пар (tickSize/stepSize/minNotional), тестнет, правила rate-limit и ошибки.
- **Результат**: документ `docs/exchange_research.md` с фактами и открытыми вопросами
  (по образцу прежнего research-документа: только подтверждённые факты, спорное — в вопросы).
- **Приёмка**: каждый факт имеет ссылку на документацию биржи; открытые вопросы перечислены;
  решение по типу рынка (спот/маржа/фьючерсы — D15) зафиксировано пользователем.

### E2. Read-only адаптер рыночных данных
- **Цель**: `exchange/<биржа>/` — реализация портов `marketdata` (история REST, потоки WS),
  BarFinalizer (финализация свечей, дедупликация), rate-limiter, маппинг ошибок,
  контрактные тесты на подменном транспорте; сверка истории API против локальных CSV.
- **Ограничения**: без ордеров; ключи — только read-only и только из окружения.
- **Приёмка**: тесты на фейк-транспорте зелёные; read-only smoke-сценарий пользователя
  с реальным ключом (отдельная инструкция); расхождения CSV/API объяснены.

### E3. Ордерный шлюз и LIVE-оркестратор
- **Цель**: реализация `BrokerGateway` (идемпотентность client_order_id, UNKNOWN_RESULT →
  сверка, reconciliation позиций), LIVE-оркестратор (warmup → поток → сигналы → RiskGuards →
  шлюз), алерты, kill-switch в цикле; тестнет-прогон.
- **Приёмка**: контрактные тесты шлюза; прогон на тестнете/минимальных объёмах под
  наблюдением; чек-лист live.md §5 выполнен; только затем — обсуждение
  `EXCHANGE_INTEGRATION_AVAILABLE = True` и реальных ордеров (P9, отдельное решение).

### Возможные расширения (после E1–E3, по решениям P1–P8)
- CatBoost-кандидат и ablation меток (triple-barrier);
- признаки из стакана/спреда (P3); мульти-символьный портфель (P5);
- дробные количества/Decimal в заявках (P7/D14); поддержка конкретного типа рынка (P8/D15).
