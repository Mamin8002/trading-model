Код: `src/tradebot/data/` (bar, csv_loader, validator, resampler, sessions, synthetic).

## 1. Формат входного CSV

```
datetime,open,high,low,close,volume
2024-01-03 18:00:00,42150.50,42210.00,42100.10,42180.20,123.456
```

- колонки — ровно требуемый набор (порядок не важен); лишние/недостающие — ошибка;
- формат совместим с экспортом свечей криптобирж (например, выгрузки Binance Vision
  после переименования колонок: `open_time→datetime` в UTC и `volume` в базовом активе);
- `datetime` — naive-метка в таймзоне `data.source_timezone` (по умолчанию UTC)
  либо ISO-8601 со смещением (`2024-01-03T18:00:00+00:00`, суффикс `Z` поддерживается);
- числа — только точка как десятичный разделитель, без разделителей тысяч;
  экспоненциальная запись (`1e-5`) допускается;
- цены — строго положительные, конечные;
- `volume` — неотрицательное число; **дробные значения разрешены** (объём криптопар
  в базовом активе дробный — decisions D13). Округление/масштабирование не выполняется;
- пустые строки пропускаются; строки с неверным числом полей — ошибка.

### Что проверяется (ошибки — загрузка отклоняется)

- схема заголовка (E_HEADER_MISSING_COLS / E_HEADER_UNKNOWN_COLS);
- парсинг дат и чисел (E_DATETIME_PARSE / E_NUMBER_PARSE / E_PRICE_INVALID / E_VOLUME_INVALID);
- дубликаты меток и порядок (E_DUPLICATE_TS / E_UNSORTED);
- OHLC-инварианты: low ≤ open/close ≤ high, low ≤ high (E_OHLC);
- соответствие меток сетке таймфрейма (E_OFF_GRID);
- пустой файл / только заголовок (E_EMPTY_FILE).

Ничего не чинится молча: данные не сортируются и не дедуплицируются — ошибки
нужно исправить в источнике (decisions D1).

### Что отмечается предупреждениями (загрузка succeeds, факт виден в отчёте)

- пропуски баров против сетки/календаря (W_GAP) — бары НЕ фабрикуются;
- нулевой объём (W_ZERO_VOLUME, отключается `validation.warn_zero_volume: false`);
- бары вне настроенных сессионных окон (W_OUT_OF_SESSION).

## 2. Время: семантика метки и таймзона (фиксированное правило)

**Правило проекта (decisions D11):**

1. Внутренний стандарт всех меток — **UTC**, семантика — **начало бара** (bar_open).
   Ядро (`Bar`) принимает только timezone-aware UTC-метки.
2. Крипторынок работает **круглосуточно**: в UTC нет ни переходов на летнее время,
   ни двусмысленностей локальных зон. Naive-метки CSV трактуются в
   `data.source_timezone` (по умолчанию **UTC** — так отдают свечи криптобиржи).
   Если ваша выгрузка в другой зоне — укажите её явно (например `Asia/Tokyo`);
   ISO-метки с собственным смещением уважаются всегда.
3. Семантика метки (`timestamp_semantics`) — ОБЯЗАТЕЛЬное поле конфига без
   значения по умолчанию: `bar_open` (метка = начало свечи) или `bar_close`
   (метка = конец; нормализуется сдвигом на длительность бара). Уточните
   семантику в документации вашей выгрузки — ошибка на один бар ломает причинность.
4. Границы «суток» для дневных риск-лимитов и календарных признаков — в
   `data.source_timezone` (по умолчанию UTC).
5. Метки, не кратные сетке таймфрейма, — ошибка (E_OFF_GRID), а не автоокругление.

Как подтвердить семантику на своих данных: сравните первую/последнюю метку суток
выгрузки с документацией биржи либо сдвиньте файл на интервал бара и посмотрите,
какой вариант даёт непрерывную сетку без W_GAP на стыке с соседним файлом.

## 3. Таймфреймы, агрегация и календарь 24/7

- поддерживаются `1m, 5m, 10m, 15m, 1h`;
- `10m` строится локально из `base_timeframe` (`5m` по умолчанию или `1m`) —
  нативных 10-минутных свечей криптобиржи обычно не отдают (decisions D3);
  правило: `base_timeframe` мельче целевого и кратен ему;
- агрегация: open — первый бара группы, high — max, low — min, close — последний,
  volume — сумма (для дробных объёмов — float-сумма);
- неполные интервалы НЕ выдаются за полные: при нехватке исходных баров интервал
  пропускается с issue `COVERAGE_INCOMPLETE` (или выдается `is_final=False` при
  явном `allow_incomplete`); хвост данных — `pending` (`is_final=False`);
- ожидаемое покрытие интервала считается по календарю сессий (если задан) либо по
  равномерной сетке;
- **календарь 24/7** (`always_on_calendar`, в конфиге — окна `00:00`–`24:00` UTC
  во все дни недели): торговое время — любой момент, включая выходные и полночь;
  конец окна `24:00` поддерживается схемой специально для круглосуточных рынков;
- секцию `sessions` можно не задавать вовсе: пропуски считаются по равномерной
  сетке (для непрерывных криптоданных результат эквивалентен календарю 24/7).

## 4. Конфигурация

```yaml
data:
  csv_dir: data/raw
  symbols:
    - ticker: BTCUSDT          # пара в формате вашей биржи (decisions D12)
      files:
        "1m": BTCUSDT_M1.csv
        "5m": BTCUSDT_M5.csv
  timestamp_semantics: bar_open   # ОБЯЗАТЕЛЬНО явно
  source_timezone: UTC            # default; другая зона — явно
  volume_units: base_asset        # base_asset | quote_asset (информационно, D13)

sessions:                         # опционально; крипторынок 24/7:
  timezone: UTC
  days:
    - days: [0, 1, 2, 3, 4, 5, 6]
      sessions:
        - { start: "00:00", end: "24:00" }
```

Файлы по таймфреймам необязательны для всех ТФ: отсутствующие строятся
ресэмплингом из `base_timeframe` (см. §3).

## 5. Демонстрационные данные

`data/demo/DEMO_M1.csv` — **СИНТЕТИЧЕСКИЕ** данные (не рыночные): 10080
минутных баров (7 суток) `2024-01-03 18:00` → `2024-01-10 17:59` **UTC**,
детерминированный шаблон (open растёт на 0.01/мин, volume на 10/мин), серия
непрерывна и проходит через полночи и выходные — проверяет обработку 24/7. Используется демо-конфигом
(`configs/demo.yaml`, `configs/sim_demo.yaml`) и офлайн-проверками.

Генератор синтетики для тестов: `tradebot.data.synthetic.generate_synthetic_bars`
(seed-воспроизводимый; `continuous=True` — круглосуточная сетка 24/7, иначе
условное демо-окно пн–пт 08:00–16:00 UTC).

## 6. Запуск проверок

### Офлайн-проверка данных (сеть и секреты не нужны)

```powershell
# сценарий крипторежима: CSV/UTC/24-7, ресэмплинг, признаки, TEST-путь, блокировка LIVE
python scripts\manual_checks\check_crypto_mode.py

# сценарий слоя данных: конфиг, CSV-валидация, агрегация (ручные эталоны)
python scripts\manual_checks\check_phase_02_data.py

# юнит-тесты
python -m pytest

# валидация демо-данных через CLI (+ агрегация в 10m)
python -m tradebot.cli.validate_data --config configs\demo.yaml --resample 10m

# валидация вашего CSV (семантику метки укажите явно; таймзона по умолчанию UTC)
python -m tradebot.cli.validate_data --csv data\raw\BTCUSDT_M1.csv --timeframe 1m --timestamp-semantics bar_open
```

### Если проверка не прошла — что прислать

1. ПОЛНЫЙ вывод сценария (от `===` до `RESULT: ...`);
2. `python --version`, операционная система;
3. `pip show tradebot pydantic PyYAML lightgbm`;
4. хвост `python -m pytest` (последние ~20 строк).

## 7. Ограничения слоя данных (зафиксировано, не угадано)

- источник данных — ТОЛЬКО локальные CSV пользователя; сетевые загрузчики истории
  не реализованы (подключение биржи — будущий этап, [live.md](live.md));
- проект не проверяет соответствие CSV реальной бирже: целостность выгрузки —
  ответственность пользователя (валидатор ловит структурные дефекты, но не
  «правильность» цен);
- внутрибарные данные (тики, траектория внутри свечи) не поддерживаются:
  симулятор стопов/целей использует консервативное правило конфликта
  ([simulation.md](simulation.md) §4);
- дробные количества для ЗАЯВОК — отдельный отложенный вопрос (decisions D14);
  дробность `volume` в данных поддерживается (D13).
