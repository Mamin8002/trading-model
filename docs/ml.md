# Обучение модели: признаки, целевая переменная, walk-forward, метрики, артефакты

Документ фазы 3 (ML-контур). Основания: [architecture.md](architecture.md) §5–§6,
[decisions.md](decisions.md) D4–D6, [roadmap.md](roadmap.md) этапы M1/M2.
Данные и CSV-контракт — [data.md](data.md).

> **Дисклеймер.** Все метрики этого контура — диагностические. Ничто в отчётах не
> является обещанием доходности; качество модели признаётся только по отложенным

## 1. Выбор библиотеки: LightGBM (обоснование)

**Основная модель — LightGBM** (`LGBMClassifier`/`LGBMRegressor`, sklearn-API):

- решения D4/architecture §5.1: градиентный бустинг — стартовый кандидат для
  табличных признаков свечей; Transformer/LSTM отложены до выполнения явных условий
  (подтверждённый потолок табличной модели + воспроизводимое улучшение на
  walk-forward + бюджет на инфраструктуру) — сейчас ни одно не выполнено;
- зависимости проекта: лёгкие CPU-колеса под Windows/Linux/macOS, Python ≥ 3.10;
  numpy/pandas и так входят в ядро стека
  (architecture §8); scikit-learn добавлен только ради метрик и логистического
  базового ориентира (тоже требование D4);
- детерминированность: `deterministic=True`, `force_row_wise=True`, `n_jobs=1`,
  фиксированный `seed` — повторный прогон даёт идентичные прогнозы (проверяется
  тестами и ручным сценарием);
- pin `lightgbm>=4.0,<5`: в 4.7 объявлен deprecated `eval_set` API — переход на 5.x
  только отдельной задачей с проверкой совместимости.

**CatBoost** — контрольный кандидат (D4/P1): в этой фазе не подключён; запрос
`model.kind: catboost` завершается явной `NotImplementedError` со ссылкой на решение,
а не молчаливой заменой библиотеки.

**Базовые ориентиры** (обязательны, D4): `majority` (постоянный класс из train-окна),
`momentum` («предыдущий знак»: класс = знак последней НАБЛЮДАННОЙ доходности
close_t/close_{t-1} − 1 — только прошлое), `logreg` (StandardScaler+LogisticRegression,
скалер фитится строго на train-окне фолда). Модель имеет смысл обсуждать как
кандидата, только если она обыгрывает все три на тех же фолдах.

## 2. Признаки (набор `v1`, 31 колонка)

Все признаки **причинные**: значение в строке t использует только бары ≤ t
(решение принимается на закрытии бара t). Периоды настраиваются в
`features.params` (дефолты документированы ниже).

| Группа | Колонки | Периоды (дефолт) |
|---|---|---|
| Доходности | `ret_{lag}` — log-доходность за lag баров | lags = 1, 3, 5, 10, 21 |
| EMA | `ema_ratio_{p}` = close/EMA(p) − 1; `ema_slope_{p}` = EMA(p)/EMA(p−1) − 1 | p = 8, 21, 50 |
| RSI | `rsi_{p}` (Уайлдер, 0..100) | p = 14 |
| MACD | `macd_norm`, `macd_signal_norm`, `macd_hist_norm` (делённые на close) | 12/26/9 |
| ATR | `atr_ratio_{p}` = ATR(p)/close (Уайлдер) | p = 14 |
| Структура свечи | `bar_range`, `bar_body`, `upper_wick`, `lower_wick` (нормированы на close); `close_position` = (close−low)/(high−low) (вырожденный бар → 0.5); `gap_prev` = open/prev_close − 1 | — |
| Волатильность | `vol_{w}` — rolling std log-доходности 1 бара; `vol_ratio` = vol_short/vol_long; `park_vol_{w}` — Паркинсон по high/low | w = 12, 48 |
| Объём | `volume_ratio_{w}` = volume/rolling_mean(volume, w); `volume_trend_{a}_{b}` = mean(a)/mean(b) − 1 | a = 20, b = 60 |
| Время | `minute_of_day`, `day_of_week` — в локальной зоне биржи (`data.source_timezone`) | — |

Свойства:
- warmup — аналитическая граница прогрева (дефолт: 61 бар); строки с NaN
  исключаются из датасета, решения по ним не принимаются;
- `lookback_bars` таймфрейма обязан быть ≥ warmup (иначе явная ошибка —
  молчаливый подбор запрещён);
- манифест (версия, параметры, точный список и порядок колонок) сохраняется с
  моделью; загрузчик отклоняет рассинхрон (см. §6);
- нормализация по всей выборке отсутствует (деревьям не нужна); единственная
  стандартизация — внутри `logreg`-ориентира, фитится на train-окне фолда
  (architecture §6.4);
- причинность подтверждена тестами: префикс-инвариантность (обрезанная серия даёт
  те же значения в прошлых строках) и возмущение будущего (изменение любых баров
  после t не меняет признаки в t) — `tests/test_features.py`, проверка 03 ручного
  сценария.

Модуль признаков НЕ импортирует модуль меток (проверяется гигиена-тестом):
будущее существует только в `labels/` и только на этапе сборки датасета.

## 3. Целевая переменная

Для бара t таймфрейма TF и горизонта H = `timeframes.<TF>.horizon_bars`:

```
fwd_return(t) = close[t+H] / close[t] − 1        (по закрытым свечам TF)
```

- `fwd_return_class` (основной, D5): y = 1 при fwd_return > +band; y = 0 при
  fwd_return < −band; внутри полосы ±band — нейтраль (строка исключается из
  обучения и оценки классификации). `band = neutral_band_bps / 10000` — задаётся
  в конфиге таймфрейма и по смыслу ≈ издержки сделки;
- `fwd_return_reg`: y = fwd_return (регрессия L2);
- `triple_barrier`: не реализован (отложен до B1+, D5) — явная ошибка при запросе.

Будущая целевая переменная не попадает в признаки конструкцией: метки строятся
отдельным модулем `labels/` при сборке датасета; признаки и inference-путь меток
не видят (architecture §6.2, гигиена-тест).

## 4. Walk-forward валидация (purged, expanding)

```
train_k = [0, val_start_k − embargo)      val_k = [val_start_k, val_end_k)
embargo = max(validation.walk_forward.embargo_bars or 0, horizon_bars)
```

- окна строго хронологические, train расширяется от начала (anchored), val идёт
  вперёд без пересечений; **случайное перемешивание не используется нигде**;
- инвариант очистки `max(train) + H < min(val)` проверяется программно для каждого
  фолда (`assert_no_label_overlap`) — перекрывающиеся целевые горизонты между
  train и val исключены (D6);
- embargo и горизонт измеряются в барах серии (индексное пространство) — разрывы
  сессий не ломают purge;
- `validation.walk_forward`: `n_splits` (≥2), `embargo_bars` (null = авто = H;
  явное значение обязано быть ≥ H — проверяет схема конфига), `min_train_bars`,
  `min_val_bars`;
- **недостаток истории**: если данных не хватает, прогон останавливается
  `InsufficientHistoryError` с расчётом требуемого минимума; train-метрики при
  этом (и вообще) не выдаются за оценку качества — в отчёте они помечены как
  диагностика переобучения;
- early stopping (если включён `model.params.early_stopping_holdout_bars > 0`)
  использует holdout в ХВОСТЕ train-окна; валидационный фолд для подбора итераций
  не задействуется. Подбор гиперпараметров на валидационных фолдах запрещён (D6):
  параметры фиксируются конфигом до обучения; если подбор появится — только
  вложенным циклом внутри train-окна, и финальный фолд остаётся нетронутым;
- **аудит утечек** (architecture §6.8, `audit_random_split: true`): дополнительно
  обучается модель на нехронологическом 80/20-сплите (seeded) и сравнивается AUC:
  `delta = AUC_random − AUC_wf_OOS`; `delta > 0.05` → флаг, блокирующий промоушен
  (признак утечки или сильной нестационарности). На синтетических демо-данных с
  режимным дрейфом флаг ожидаемо взводится — это демонстрация работы аудита, а не
  дефект пайплайна; на реальных данных устойчивый флаг требует разбора до
  дальнейшего тюнинга.

## 5. Метрики

### 5.1 ML (по каждому фолду и по объединённому OOS)

- классификация: accuracy, balanced accuracy, ROC-AUC, log-loss, confusion matrix
  (в окне одного класса AUC/log-loss = «н/д», а не подмена);
- регрессия: MAE, RMSE, R².

OOS = конкатенация прогнозов всех валидационных окон (хронологически, без
пересечений) — «итоговый отложенный период».

### 5.2 Торговые (упрощённая диагностическая симуляция фазы 3)

Полный событийный симулятор — этап B1 (roadmap). Сейчас:
- позиция long-only: 1, если P(up) ≥ `evaluation.decision_threshold` (для
  регрессии — знак прогноза), иначе 0;
- исполнение: сигнал на закрытии t → вход по open[t+1] → выход по open[t+2]
  (architecture §6.6: исполнение не раньше открытия следующего бара);
- издержки: `(commission_bps + slippage_bps)` на единицу оборота |Δпозиции|,
  включая принудительную ликвидацию в конце сегмента;
- сегменты фолдов независимы (позиция не переносится через разрыв между окнами);
- внутрибарное исполнение (high/low) НЕ моделируется — заведомое упрощение.

Выходные метрики: чистая доходность (compounded, после издержек), валовая
доходность, издержки, максимальная просадка, оборот (turnover), число сделок,
exposure, hit-rate сделок, profit factor, Sharpe и CAGR (годовые).

### 5.3 Сравнение с базовыми ориентирами

Те же фолды, те же метрики и та же торговая симуляция для majority/momentum/logreg;
в отчёте — таблицы «модель vs ориентиры» и явный вывод, обыгрывает ли модель
ориентиры (условие D4 для обсуждения промоушена).

### 5.4 Допущения годового пересчёта (обязательно фиксируются в отчёте)

- `bars_per_year`: из конфига (`evaluation.bars_per_year`) ИЛИ вывод из данных —
  медиана баров на торговый день (локальная зона `data.source_timezone`) ×
  `trading_days_per_year` (дефолт 365 — крипторынок без выходных, decisions D11); источник («config»/«derived») печатается;
- Sharpe = mean(r−rf_bar)/std(r)·√bars_per_year, rf_bar из `risk_free_annual`
  (дефолт 0 — допущение фиксируется);
- CAGR = (1 + net_return)^(bars_per_year / n_oos_bars) − 1;
- комиссии/слиппедж — ОЦЕНОЧНЫЕ допущения, а не фактические тарифы биржи.

### 5.5 Вердикт

`validation.thresholds` (`min_oos_auc`, `min_oos_trades`) задаются ДО обучения.
Вердикт — «диагностические пороги пройдены/не пройдены» + статус аудита утечек.
Формулировка вердикта явно не утверждает прибыльность.

## 6. Артефакты модели и воспроизводимость

Каталог артефакта `models/<experiment_id>_<TF>_<fingerprint>/`:

| Файл | Содержимое |
|---|---|
| `model.lgb.txt` | текстовая модель LightGBM |
| `metadata.json` | период обучения (first/last ts, число строк), таймфрейм, горизонт, lookback, метка (kind, band), параметры модели + seed + эффективное n_estimators, сводка walk-forward ( embargo, границы и метрики фолдов), результаты OOS и ориентиров, торговые метрики, допущения, аудит, вердикт, хэш конфига, fingerprint датасета, версии библиотек (python, tradebot, numpy, pandas, lightgbm, scikit-learn, pyarrow, pydantic) |
| `feature_manifest.json` | версия набора v1, параметры периодов, точный список и порядок колонок, warmup |
| `oos_predictions.csv` | прогнозы объединённого OOS (ts, y, prediction, position) |

Отчёт: `reports/train_report_<...>.md` (разделы: параметры, признаки, метка,
сплиты, метрики по фолдам, OOS, ориентиры, торговые метрики + допущения, аудит,
вердикт, воспроизводимость).

Загрузка: `tradebot.ml.registry.load_model_bundle(dir)` → `ModelBundle`;
`validate_compatibility(timeframe=..., feature_names=..., horizon_bars=...,
label_kind=...)` отклоняет несовместимый контекст перечислением ВСЕХ расхождений
(`ModelCompatibilityError`); `predict_proba(bars)` пересобирает признаки по
манифесту модели и сверяет колонки до прогноза.

Финальная модель в артефакте обучена на всех строках датасета фиксированными
параметрами (при включённом early stopping — медиана best_iteration фолдов);
приведённые метрики получены ТОЛЬКО на валидационных окнах и финальной модели
не присвоены (это отмечено в metadata.note и в отчёте).

Воспроизводимость: seed в конфиге; LightGBM в детерминированном режиме
(`deterministic`, `force_row_wise`, `n_jobs=1`); данные не перемешиваются;
повторный прогон на той же версии библиотек даёт идентичные прогнозы (проверка
в тестах и ручном сценарии).

## 7. Запуск

Установка зависимостей (PowerShell, из корня репозитория):

```powershell
python -m pip install -e ".[dev,ml]"
```

Обучение на своих данных (офлайн, CSV из `data.csv_dir`):

```powershell
# заполните configs\ml_example.yaml: файлы CSV, timestamp_semantics,
# lookback_bars/horizon_bars, neutral_band_bps, пороги
python -m tradebot.cli.train --config configs\ml_example.yaml --timeframe 5m
# 10m — из базового файла 5m (ресэмплинг, решения D3):
python -m tradebot.cli.train --config configs\ml_example.yaml --timeframe 10m
```

Коды возврата CLI: 0 — прогон завершён (вердикт печатается и может быть
отрицательным); 2 — ошибка конфига; 3 — недостаточно истории; 4 — ошибка
данных/обучения.

Ручная проверка фазы (синтетические данные, без сети и секретов):

```powershell
python scripts\manual_checks\check_phase_03_ml.py
```

Ожидаемый вывод: 15 строк `PASS`, список созданных файлов
(`models/phase03_manual*/...`, `reports/phase03_manual*/...`), итог
`RESULT: PASS (15/15 checks)`, код возврата 0.

Тесты:

```powershell
python -m pytest
```

## 8. Ограничения фазы (явно НЕ сделано)

- полный событийный симулятор со стопами/внутрибарными филлами/бюджетом — этап B1;
- CatBoost-кандидат и финальный выбор библиотеки — после сравнения (P1);
- подбор гиперпараметров (вложенный в train-окно) — отдельная задача; сейчас
  параметры фиксированы конфигом;
- признаки из стакана/спреда — после реализации потокового адаптера биржи (P3);
- LIVE-инференс модели (стратегия/исполнение) — этапы E2/E3 (не реализованы);
- мульти-символьное обучение — один прогон = один символ/таймфрейм.
