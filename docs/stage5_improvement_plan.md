## 5a. Модель v2: горизонт 10–15 мин + честная торговая оценка

### Что именно прогнозирует модель (фиксируется в model card и отчёте)

**Направление движения цены на горизонте H баров**: y = +1, если close(t + H·Δ) > close(t),
иначе −1 (обобщение подхода исходного ноутбука). Модель выдаёт **вероятность роста**
P(up); уверенность = max(P, 1−P). Это НЕ ожидаемая доходность и НЕ вероятность касания
уровня (triple-barrier — осознанно не делаем в этом этапе: усложнение разметки при том,
что направление — требуемый минимум; может быть следующим шагом).

Горизонт: `model.horizon_bars` — **default 3 (=15 мин при interval=5)**; 2 = 10 мин.
Любое значение 2–3 покрывает требуемый диапазон 10–15 мин. Смена горизонта = переобучение
(существующий guard это контролирует).

### Признаки v2 (только закрытые бары ≤ t — будущих данных нет)

Набор `v2` (~10 признаков, все вычислимы в момент закрытия бара t):
- доходности: ret_1, ret_3, ret_H (close_t/close_{t−k} − 1);
- форма бара: body=(close−open)/close, range=(high−low)/close, upper/lower shadow;
- объём: vol_ratio_20 = volume_t / mean(volume_{t−1..t−20});
- время суток: sin/cos минут дня (UTC).
Warm-up: первые 20 баров исключаются (счёт в отчёте, данные не фабрикуются).
Набор `ratio` (v1) сохраняется для сравнения на тех же окнах.

### Протокол сравнения (walk-forward, те же 8 окон, embargo t+(H+1)·Δ ≤ test_start)

Варианты: **v1** (ratio, порог 0.55 фиксированный), **v1+thr** (ratio, порог выбирается
без утечки), **v2** (новые признаки, порог без утечки), **baselines** (majority, momentum,
«случайный вход с теми же издержками»).

**Порог входа без утечки**: внутри каждого окна — внутренний валидационный срез
(последние 15% обучающей части, отделённый embargo), отдельный fit на остальных 85%,
выбор порога из сетки {0.50..0.75, шаг 0.01} по net-PnL/сделку на срезе; затем финальный
fit на всей обучающей части, выбранный порог заморожен на тестовое окно.

### Торговый симулятор (оценка с комиссиями и проскальзыванием)

Конфиг `trading: {fee_pct: 0.1, slippage_pct: 0.02}` (односторонние, % от цены; дефолты —
Bybit spot taker; пользователь может задать свои). Правила симуляции (единые для всех
вариантов):
- вход по close сигнального бара ± slippage (в сторону входа); размер — фиксированная
  котировочная сумма (для сравнения вариантов — 100 USDT);
- выход: close(t+H) ∓ slippage, ИЛИ досрочно по настроенным правилам выхода
  (SL/TP/max_hold из `positions.exit_rules` — проверяются по high/low/close закрытых баров;
  если TP и SL в одном баре — считается SL, консервативно);
- комиссии: fee_pct с каждой стороны.
Метрики на окно и агрегат: **net return per trade (%)**, total net %, n trades, win rate,
max drawdown по кривой, gross (без издержек) — для прозрачности.

### Критерий замены модели (предрегистрация — ДО запуска прогонов)

- Первичная метрика: **агрегированный net return per trade** (после комиссий+слиппеджа)
  на 8 отложенных walk-forward окнах.
- Вторичная: accuracy направления на горизонте.
- **v2 заменяет v1 как production только если**: primary(v2) > primary(v1) И
  primary(v2) > primary(majority-baseline). Иначе v1 остаётся, v2 сохраняется с флагом
  `adopted: false` в model card (бот его не подхватывает; `find_latest_model_dir`
  учитывает флаг).
- Ожидаемая честная оговорка: при текущем уровне преимущества net-метрика, вероятно,
  отрицательна у ВСЕХ вариантов — «принять» означает «лучше текущей и baseline»,
  а не «прибыльно».

### Артефакты этапа 5a

- `scripts/train_model.py` расширяется: сравнение вариантов, торговый симулятор,
  adopt-gate, отчёт **`docs/validation_report_v2.md`** (отчёт v1 не перезаписывается),
  артефакт `data/models/xgb-...-h3-v2-<ts>/` (или adopted:false).

  признаки бара t); 2) цель H=2/H=3 корректна (10/15 мин); 3) порог выбирается только
  на train-срезе (контроль аргументов); 4) математика симулятора на ручном примере

## 5b. Непрерывный анализ рынка + paper trading

### Внутрисвечной поток

- Подписка `publicTrade.{symbol}` (+ существующие kline/tickers). Событие TradeEvent
  (цена, время, сторона, объём) в общей событийной модели (`streaming/base.py`).
- Трекер внутрисвечного движения: изменение цены от open формирующейся свечи и за
  скользящее окно `intrabar.window_s` (default 60 c).
- Правило spike: движение ≥ `intrabar.spike_pct` (default 0.15%) за окно → **алерт
  «быстрое движение»**, НЕ сигнал на вход. Вход по алерту запрещён без фильтров:
  данные fresh + соединение OK + нет конфликтующей позиции + (по умолчанию)
  подтверждение моделью на следующем закрытом баре (`spike_requires_model_confirm: true`).
- Статус источника и время последнего обновления — в дашборде (уже есть для kline/ticker,
  расширяется на trade-поток). Задержка/разрыв/неполнота → существующая маркировка
  STALE/не актуален распространяется и на spike-алерты.

### Paper trading (виртуальные позиции; ордеров и приватного API нет)

Конфиг `paper`:
```yaml
paper:
  enabled: true                # виртуальная торговля в LIVE; в TEST — флаг --paper
  initial_balance_quote: 10000 # виртуальный баланс, USDT
  order_size_quote: 100        # виртуальный объём сделки, USDT
  entry_min_confidence: null   # null = model.confidence_threshold
  cooldown_bars: 1             # пауза после закрытия
  max_open_positions: 1        # конфликтующие позиции не открываются
  intrabar_exits: true         # SL/TP по тикам в LIVE (в TEST/реплее — по барам)
  partial_tp: {enabled: false, at_pct: null, fraction: 0.5}
```
Издержки — из `trading` (fee_pct/slippage_pct), применяются к каждой виртуальной сделке.
Правила выхода — `positions.exit_rules` (TP/SL/max_hold); **без заданных правил вход
воздерживается** (ABSTAIN, как в текущей логике советника). Правила фиксируются
снимком в момент открытия позиции и не меняются молча во время работы.

Действия на каждый свежий сигнал / бар / тик (с объяснением причины):
- **OPEN_VIRTUAL**: свежий BUY, уверенность ≥ порога, правила выхода заданы, нет открытой
  виртуальной позиции, cooldown истёк, данные fresh;
- **HOLD**: позиция открыта, сигнал в том же направлении или HOLD, правила не сработали;
- **CLOSE**: сработало SL/TP/max_hold (указывается КАКОЕ правило и его уровень) или
  встречный SELL-сигнал модели;
- **PARTIAL_CLOSE**: при включённом partial_tp — закрытие fraction на уровне at_pct;
- **ABSTAIN**: нет правил выхода / данные не fresh / cooldown / конфликт.

Учёт: журнал — отдельная коллекция `paper_positions` (НЕ смешивается с ручными позициями
пользователя); баланс, equity, комиссии, слиппедж, время входа/выхода, версия модели и
исходный сигнал каждой виртуальной сделки; персистентность после перезапуска;
`position_cli.py paper-stats / paper-list / paper-history`.
UI: блок «Paper: баланс, открытая виртуальная позиция (вход, PnL с учётом издержек),
последнее действие + причина, история действий».
Демо: `run_bot.py --mode TEST --replay-bars N --paper` — полный цикл офлайн.

### Ручная проверка 5b

`scripts/manual_checks/check_stage5b_paper.py` (офлайн, демонстрационные данные):
1) spike-детектор на синтетических тиках (срабатывает/не срабатывает, фильтр fresh);
2) задержка/разрыв → алерты и действия помечаются недоступными;
3) paper-цикл: OPEN на BUY с правилами → HOLD на повторный BUY → CLOSE по SL
(тиковому и баровому), TP, max_hold, встречному сигналу (с указанием правила и причины);
4) PARTIAL_CLOSE математика; 5) комиссии/слиппедж в балансе (ручной расчёт);
6) ABSTAIN без правил выхода и при конфликте; 7) персистентность после «перезапуска»;
8) скан: отсутствие ордерных/приватных эндпоинтов.

## Порядок выполнения и приёмка

1. **5a** (модель v2 + симулятор + adopt-gate + отчёт v2) → stop → пользователь запускает
   `check_stage5a_model.py` и (опционально) полный `train_model.py` → обратная связь.
2. **5b** (внутрисвечной поток + paper trading) → stop → пользователь запускает

3. Финальный отчёт: какие метрики сравнивались, на каких периодах, итог v2 vs v1 vs

## Ограничения и честные оговорки (фиксируются заранее)

- Улучшение точности или прибыльности **не обещается**; adopt-gate защищает от ухудшения,
  а не гарантирует доход. При издержках ~0.2% round-trip и горизонте 10–15 мин ожидаемый
  net-результат всех вариантов, скорее всего, останется отрицательным — отчёт покажет это явно.
- Тиковые выходы paper — аппроксимация (очередь/частичные исполнения не моделируются).
- Порог, выбранный на внутреннем срезе, всё равно даёт небольшой оптимизм (выбор по шуму);
  сравниваем все варианты одинаковым протоколом.
- Public trade stream: до 1024 сделок в сообщении — агрегируются, UI не перегружается.
- Модель по-прежнему не является основанием для реальной торговли; paper trading —
  инструмент проверки логики.
