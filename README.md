# BTC Bybit Monitor Bot

Бот мониторинга BTC и генерации торговых сигналов **BUY / SELL / HOLD** на публичных
рыночных данных Bybit (V5 API). Модель — перенос подхода из репозитория
[Sumit2514/Bitcoin-Price-Prediction](https://github.com/Sumit2514/Bitcoin-Price-Prediction)
(5-минутный ноутбук: признаки OHLCV, цель — направление следующего бара, XGBoost)
на свежие данные Bybit с хронологической walk-forward-валидацией.

> **Дисклеймер.** Сигналы — вывод статистической модели, а не гарантия дохода и не
> персональная финансовая рекомендация. Бот **не** размещает ордера, **не** использует
> приватные API, **не** запрашивает баланс и **не** требует ключей. Фактические позиции
> учитываются только после ручной регистрации.

> **📖 Полный гайд по использованию: [`docs/user_guide.md`](docs/user_guide.md)** —
> установка, настройка (включая горизонт прогноза и условия выхода), запуск TEST/LIVE,
> чтение дашборда, регистрация и сопровождение позиций, FAQ, решение проблем,
> ограничения модели. README ниже — краткая справка.

## Конфигурация — `config/default.yaml`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `mode` | `TEST` | `TEST` — офлайн-реплей; `LIVE` — публичный WS Bybit |
| `exchange.symbol/category/interval` | `BTCUSDT`/`spot`/`"5"` | инструмент настраивается; категория spot/linear/inverse |
| `model.horizon_bars` | `3` | **на сколько баров вперёд смотрит модель** (3 × 5 мин = **15 мин**; 2 = 10 мин). Смена требует переобучения |
| `model.confidence_threshold` | `null` | `null` = порог из model card (выбран при обучении без утечки); число = ручное переопределение; ниже порога → HOLD |
| `model.feature_set` | `auto` | `auto` = сравнить ratio/v2 и применить adopt-gate; `ratio` (v1); `v2` (лаг-признаки); `raw` (как в оригинале) |
| `trading.fee_pct / slippage_pct / order_size_quote` | `0.1 / 0.02 / 100` | издержки и объём для симуляции и paper trading |
| `signals.stale_after_intervals` | `3` | порог устаревания данных (× интервал) |
| `positions.exit_rules.*` | `null` | **явные** TP/SL/max_hold; пока не заданы — рекомендация на вход воздерживается |
| `ui.mode` | `auto` | `line` (строка на месте + события) / `dash` (полный экран ANSI) / `block` (снимки по изменению) |
| `journal.path` | `data/journal/journal.json` | журнал сигналов и позиций |

Секреты в конфигурации не используются и не должны появляться.

## Данные (Этап 2a)

```powershell
python scripts\download_history.py [--start 2024-01-01] [--end 2026-06-30]
python scripts\manual_checks\check_stage2_data.py     # ожидание: RESULT: PASS (12)
```

Файлы: `data\raw\*.csv` + `*.metadata.json` (инструмент, категория, интервал, период,
дата загрузки, **покрытие и диапазоны архивных пропусков**), `data\processed\*.clean.csv`
+ `*.clean.report.json`. Дубликаты удаляются, порядок строго по возрастанию времени,
незакрытые свечи исключаются, пропуски (gaps) детектируются и логируются, но
**не заполняются** — данные не фабрикуются.

**Границы архива Bybit**: у биржи встречаются сегменты архива (для spot BTCUSDT 5m —
около **2022-04-11 13:10 UTC**), где сервер на запрос со `start` у границы возвращает
страницу, заканчивающуюся ДО `start`, а данные возобновляются позже (реальный пропуск
архива ~4 дня: 2022-04-11 13:10 → 2022-04-15 17:15, ~1200 баров). Загрузчик
автоматически восстанавливается зондированием вперёд (1ч/6ч/1д/3д/7д/14д/28д), склеивает
сегменты, а отсутствующие бары **не заполняет** — они попадают в итог загрузки:

```
Диапазоны пропусков:   1 (всего отсутствующих баров: 1200)
Покрытие:              99.76% загруженного диапазона
ОТСУТСТВУЮЩИЕ ДИАПАЗОНЫ (архив биржи неполон; бары НЕ заполнялись):
  2022-04-11 13:10 -> 2022-04-15 17:15  (1200 баров)
```

Обрыв загрузки раньше конца периода теперь всегда виден по строке «Покрытие» и
предупреждению о последней свече (проверка A7 в `check_stage2_data.py`).

**Надёжность долгой загрузки**: транзиентные ошибки Bybit (`retCode 10016`
«internal error», `10006`/`10018` rate limit, HTTP 429/5xx, сетевые сбои)
ретраятся автоматически с backoff (проверка A8). Если запросы всё же исчерпаны,
уже скачанные бары **не теряются**: сохраняется частичный файл
`data\raw\..._PARTIAL_fetched....csv` (в метаданных `complete: false`),
и загрузку можно продолжить без повторного скачивания начала:

```powershell
python scripts\download_history.py --resume data\raw\bybit_..._PARTIAL_fetched....csv
```

Частичные файлы (`_PARTIAL`) никогда не выбираются автоматически для обучения
или реплея — только полный датасет после успешного `--resume` (проверка A9).

## Модель (Этап 2b)

```powershell
python scripts\train_model.py            # полная валидация + финальный артефакт
python scripts\train_model.py --quick    # быстрый смоук-прогон
python scripts\manual_checks\check_stage2_model.py   # ожидание: RESULT: PASS (6)
```

- Цель (как в оригинальном ноутбуке): `y = +1`, если close через `horizon_bars` баров выше,
  иначе `-1` (ничья → `-1`); XGBoost с параметрами по умолчанию + фиксированный seed.
- Walk-forward: expanding window, 8 окон, переобучение на каждом окне, **embargo**
  (в обучение попадают только строки, чья метка полностью известна до начала окна) —
  утечка будущих данных исключена.
- Сравнение: `raw` vs `ratio` vs majority/momentum baselines vs протокол оригинала
  (single split 75/25). Итоги на данных 2024-01-01→2026-10-21: `ratio` acc **0.5059**
  против majority 0.4981; acc при уверенности ≥0.55 — 0.5142 (покрытие 21.3%).
- Артефакт: `data\models\<model_version>\` — `model.joblib`, `model_card.json`
  (версия, инструмент, горизонт, признаки, метрики, версии библиотек, ограничения),
  `walk_forward.json`. Отчёт: `docs\validation_report.md`.
- Predictor отклоняет артефакт, если конфиг (symbol/interval/**horizon_bars**) не
  соответствует model card.

### Ограничения модели (честно)

- Превосходство над baseline статистически заметно (~5σ на 118k оконных прогнозов), но
  мало: ожидаемый валовой выигрыш ≈ **0.001% на сигнал** против ~0.2% комиссий
  round-trip — **для комиссионной торговли на 5-минутном горизонте недостаточно**.
- Accuracy ≠ прибыльность; спред/комиссии/слиппедж в метриках не учитываются.
- Исходная модель из репозитория невоспроизводима (нет данных и артефакта) — сравнение
  выполнено по протоколу. Метрики из README автора проверке не подлежат.
- Модель деградирует при смене рыночного режима; рекомендуется периодическое
  переобучение (`train_model.py`) вручную. Автопереобучение на результатах позиций
  намеренно не реализовано.

### Режимы интерфейса (`--ui` или `ui.mode` в конфиге)

| Режим | Поведение |
|---|---|
| `auto` (по умолчанию) | `dash` в настоящем терминале с ANSI/VT; иначе `line` |
| `line` | **одна статусная строка обновляется НА МЕСТЕ** (`\r`, новые строки не добавляются); значимые события (новый сигнал раз в ~5 мин, смена соединения, STALE, рекомендация) печатаются отдельными строками. Работает везде: PowerShell, PyCharm, cmd |
| `dash` | полноэкранный дашборд на alternate screen: перерисовка на месте, scrollback не засоряется (Windows Terminal / полноценная консоль) |
| `block` | полный снимок печатается только при изменениях (для логов/перенаправления) |

Пример статусной строки (`line`):

```
● 19:28:45 UTC | CONNECTED | ✓ 2с | 84,456.7 | свеча 19:25 C 84,456.7 | ▲ BUY 0.582 @19:25:01 UTC | pos-000001 +0.12% | [ДЕРЖАТЬ]
```

Пример событийных строк (печатаются только при событиях, не каждую секунду):

```
[19:25:01 UTC] ▲ СИГНАЛ BUY conf 0.582 | цена 84,456.70 | бар 19:20:00 UTC→19:25:00 UTC | горизонт 5 мин | модель xgb-...
    → Рекомендация [ВХОД_ВОЗДЕРЖАНИЕ]: настройте явные условия выхода ...
[19:28:15 UTC] ● Соединение: CONNECTED (подписка подтверждена)
[19:40:00 UTC] ⚠ Данные: STALE (нет обновлений 960 с (порог 900 с))
```

Цвет и Unicode-символы (●▲▼◆✓⚠) включаются автоматически при поддержке терминалом;
`ui.colors: off` в конфиге отключает цвет, в терминалах без UTF-8 используются ASCII-символы.

Полный дашборд (`dash`/`block`) показывает: цену (ticker), последние закрытые свечи и
формирующуюся свечу, состояние соединения, свежесть данных (FRESH/STALE), текущий сигнал
(действие, уверенность, время выдачи, время бара, цена, версия модели, горизонт), историю
сигналов, открытые позиции и рекомендацию советника.

Правила: сигнал — только после закрытия свечи (`confirm=true`); ping каждые 20 с;
reconnect с backoff 1→60 с и REST-догрузкой пропущенных баров; при устаревших/неполных
данных новый сигнал помечается **не актуальным** (`data_fresh=false`) с перечислением
причин; seed истории при старте сигналы не порождает.

## Позиции и сопровождение (Этап 4)

Журнал `data\journal\journal.json` хранит историю всех сигналов и ручные позиции
(переживает перезапуск; в TEST-реплее по умолчанию используется отдельный
`journal_test.json`, чтобы демо-сигналы не смешивались с боевой историей).

```powershell
# сигналы (модель) и позиции (факты пользователя) РАЗДЕЛЕНЫ:
python scripts\position_cli.py signals --last 20

# зарегистрировать фактический вход (опционально привязав к сигналу и задав условия выхода)
python scripts\position_cli.py register-entry --price 84500 --quantity 0.01 --signal-id sig-000123 --tp 1.5 --sl 1.0 --max-hold 12 --time "2026-10-22 10:15"

# частичное закрытие
python scripts\position_cli.py close --position-id pos-000001 --price 85000 --quantity 0.004

# полное закрытие (остаток)
python scripts\position_cli.py close --position-id pos-000001 --price 84800

python scripts\position_cli.py list --all
python scripts\position_cli.py show --position-id pos-000001
python scripts\position_cli.py stats
python scripts\position_cli.py events --last 20
python scripts\manual_checks\check_stage4_positions.py   # ожидание: RESULT: PASS (11)
```

Семантика и правила сопровождения:

- Сигнал **не считается исполненным**, пока вход не зарегистрирован вручную
  (`register-entry`); регистрация с `--signal-id` связывает позицию с сигналом и
  фиксирует: время сигнала, цену, горизонт прогноза, версию модели, условия выхода.
- Для **spot BTCUSDT SELL = закрыть/уменьшить подтверждённую длинную позицию**.
  Шорты не поддерживаются (регистрация SHORT отклоняется).
- Пока позиция открыта, каждый новый свежий сигнал сначала оценивает ЕЁ:
  **ДЕРЖАТЬ / РАССМОТРЕТЬ ЗАКРЫТИЕ / НАБЛЮДАТЬ**. Встречный сигнал сопровождается
  объяснением причины и списком сработавших настроенных условий выхода.
- Условия выхода — только явно заданные (`positions.exit_rules` в конфиге или
  `--tp/--sl/--max-hold` при регистрации). Уровни стоп-лоссов/целей/сроков **не
  изобретаются**; пока правила не заданы, рекомендация на вход воздерживается.
- Если открытых позиций нет, а модель дала SELL: бот сообщает, что **фактическое
  состояние портфеля неизвестно**, и не утверждает, что нужно что-то закрывать.
- При устаревших данных рекомендации по управлению позицией не выдаются.
- Журнал фиксирует: сигналы с ценой на момент выдачи, подтверждения входа/выхода,
  причины смены статуса и результат позиции (PnL по ручным данным). Правила сигналов
  не меняются и модель на результатах позиций автоматически не переобучается.

## Этап 5a: модель v2 (горизонт 15 минут) и торговая оценка с комиссиями

```powershell
python scripts\train_model.py                          # сравнение вариантов + adopt-gate + артефакты (~2 мин)
python scripts\manual_checks\check_stage5a_model.py    # ожидание: RESULT: PASS (9)
```

- **Что прогнозирует модель v2**: вероятность НАПРАВЛЕНИЯ движения цены через
  `horizon_bars` баров (default 3 × 5 мин = **15 минут**; 2 = 10 минут). Не ожидаемая
  доходность и не вероятность касания уровня — зафиксировано в model card и отчёте.
- **Признаки v2** (только закрытые бары ≤ t): лаг-доходности ret_1/ret_3/ret_H, форма
  бара (body/range/тени), volume_ratio_20, время суток (sin/cos). Warm-up 20 баров
  исключается честно.
- **Порог уверенности выбирается без утечки**: внутренний срез обучающего окна
  (последние 15%, отделены embargo), критерий — net return на сделку; на тестовом окне
  заморожен. Итоговый порог финальной модели хранится в model card
  (`model.confidence_threshold: null` в конфиге = использовать его).
- **Торговый симулятор** (`trading.*`): вход по close сигнального бара ± слиппедж,
  выход по горизонту H или SL/TP/max_hold по закрытым барам (SL приоритетнее TP),
  комиссии с обеих сторон; baseline'ы (majority/momentum) торгуются тем же симулятором.
- **Adopt-gate (предрегистрирован)**: v2 заменяет v1 только если net-return/сделку на
  8 отложенных окнах строго лучше И текущей модели, И majority-baseline. Иначе артефакт
  v2 сохраняется с `adopted: false` и бот его не подхватывает.
- Отчёт: `docs\validation_report_v2.md` (отчёт v1 не перезаписывается).

Результаты прогона в песочнице (2024-01-01 → 2026-10-21, 8 окон, издержки 0.1%+0.02%):

| Вариант | Acc | Сделок | Net/сделку | Gross/сделку |
|---|---|---|---|---|
| v1_fixed (ratio @0.55) | 0.5071 | 15 443 | −0.2377% | +0.0023% |
| v1_sel (ratio, порог без утечки) | 0.5071 | 516 | −0.2374% | +0.0026% |
| **v2_sel (принят gate'ом)** | **0.5089** | 1 211 | **−0.2290%** | +0.0110% |
| majority (baseline) | — | 29 512 | −0.2413% | −0.0013% |
| momentum (baseline) | — | 29 512 | −0.2419% | −0.0019% |

**Честно**: v2 принят gate'ом как «строго лучше текущей модели и baseline», но net
отрицателен у всех — при издержках ~0.24% round-trip преимущество модели (~0.01%
gross/сделку) их не покрывает. Это исследовательский мониторинг, не торговый алгоритм.
Порог финальной модели выбран 0.75 — сигналы BUY/SELL будут редкими (это осознанный
результат выбора по net-метрике); для более частых сигналов задайте
`model.confidence_threshold: 0.55` вручную (osознанно снижая планку качества).

## Этап 5b: внутрисвечной анализ + paper trading

**Внутрисвечной анализ** (LIVE): подписка на публичный поток сделок `publicTrade.BTCUSDT`;
трекер быстрого движения за скользящее окно (`intrabar.window_s`, default 60 с). Движение
≥ `intrabar.spike_pct` (default 0.15%) → **АЛЕРТ «быстрое движение», НЕ сигнал входа**:
вход возможен только по модели на закрытом баре и только через фильтры стратегии. В дашборде
видны движение за окно и последняя сделка; при задержке/разрыве данные помечаются STALE.

**Paper trading** (виртуальные позиции; ордеров и приватного API нет):

```powershell
# LIVE: paper включён по умолчанию (paper.enabled: true)
python scripts\run_bot.py --mode LIVE

# TEST-демо полного цикла офлайн (правила задаются ЯВНО):
python scripts\run_bot.py --mode TEST --replay-bars 120 --speed 0 --paper --tp 0.3 --sl 0.2 --max-hold 6 --threshold 0.55 --journal data\manual_checks\paper_demo.json

# просмотр виртуальной статистики
python scripts\position_cli.py paper-stats
python scripts\position_cli.py paper-list --all
python scripts\position_cli.py paper-history --last 30

# ручная проверка этапа (офлайн, ~15-30 с)
python scripts\manual_checks\check_stage5b_paper.py    # ожидание: RESULT: PASS (10)
```

Действия бота по каждой виртуальной позиции (каждое с причиной, всё в журнале):
- **OPEN_VIRTUAL**: свежий BUY ≥ порога, правила выхода определены, cooldown истёк, нет
  открытой виртуальной позиции; комиссия и слиппедж списываются явно;
- **HOLD**: позиция открыта, сигнал не встречный, правила не сработали;
- **CLOSE**: сработало правило — `stop_loss_pct` / `take_profit_pct` (SL приоритетнее TP
  в одном баре), `max_hold_bars`, `horizon` (горизонт прогноза истёк — сигнал больше не
  действителен) или `model_counter_signal` (встречный SELL);
- **PARTIAL_CLOSE**: опциональная частичная фиксация (`paper.partial_tp`);
- **ABSTAIN**: HOLD-сигнал, SELL без позиции (шорт не открывается), данные не актуальны,
  cooldown, правила выхода не заданы (если `exit_at_horizon: false`).

SL/TP в LIVE проверяются по тикам сделок (`paper.intrabar_exits: true`), в TEST/реплее —
по закрытым барам. Правила выхода фиксируются **снимком** при открытии позиции и не
меняются молча. Виртуальные позиции хранятся в журнале отдельно от ручных позиций
пользователя и переживают перезапуск. Издержки — из `trading.*` (задаются явно).

## Режимы и безопасность

- **TEST**: офлайн-реплей сохранённых данных + демонстрационные сценарии (включая STALE);
  ручные проверки этапов по умолчанию офлайн; read-only проверки публичного Bybit —
  отдельными флагами (`--live`).
- **LIVE**: публичные WS/REST Bybit, отображение сигналов, сопровождение вручную
  зарегистрированных позиций.
- Размещение/изменение/отмена ордеров, приватные API, балансы и ключи **отсутствуют**;
  структурный скан кода на их отсутствие входит в ручные проверки (A9/A11).
- Компоненты Finam/MOEX в проекте отсутствуют (workspace был пуст; удалять было нечего).

## Структура

```
btc_bot/
  config.py               # конфигурация (dataclasses + YAML)
  data_sources/           # интерфейс MarketDataSource + Bybit REST (для будущих бирж)
  streaming/              # события, StreamProcessor (confirm/gaps/freshness), WS-клиент Bybit
  data/                   # store (raw CSV + metadata), prep (очистка, датасет)
  model/                  # features, train (артефакт+card), walk_forward, predictor
  signals/engine.py       # BUY/SELL/HOLD + уверенность + gating по свежести
  portfolio/              # journal (сигналы+позиции), advisor (сопровождение)
  ui/console.py           # консольный дашборд
  bot.py                  # оркестратор TEST (реплей) / LIVE (WS)
scripts/                  # download_history, train_model, run_bot, position_cli, manual_checks/
config/default.yaml       # конфигурация
data/                     # raw/, processed/, models/, journal/, manual_checks/ (не коммитится)
docs/                     # план этапа 1, отчёт валидации
reference_model/          # копия ноутбуков исходного репозитория (сверка подхода)
tests/                    # офлайн unit-тесты (25)
```

Интерфейсы `MarketDataSource` (REST) и событийная модель `streaming/base` (WS) позволяют
подключить другую биржу без изменения остального кода.

## Решение проблем

- **UserWarning XGBoost о pickle при загрузке модели**: артефакт сохранён другой версией
  XGBoost. Безвредно; устраняется локальным переобучением `python scripts\train_model.py`.
- **Вывод «множится» / старые кадры дашборда**: с версии UI-2 по умолчанию в терминалах
  без полноценного ANSI используется режим `line` — одна строка обновляется на месте,
  события печатаются редко. Принудительно: `--ui line` (строка на месте), `--ui dash`
  (полный экран на alternate screen, только терминалы с VT), `--ui block` (снимки по
  изменению, для логов). `NO_ANSI=1` отключает ANSI целиком.
- **403 от Bybit**: превышен IP-лимит (600 запросов/5 с) — подождите ~10 минут;
  загрузчик истории троттлит запросы автоматически.
- **Журнал повреждён**: бот не перезаписывает его молча — восстановите файл вручную
  (события и позиции хранятся в `data\journal\journal.json`).
