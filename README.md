# BTC Bybit Monitor Bot

Бот мониторинга BTC и генерации торговых сигналов **BUY / SELL / HOLD** на публичных
рыночных данных Bybit (V5 API). Модель — перенос подхода из репозитория
[Sumit2514/Bitcoin-Price-Prediction](https://github.com/Sumit2514/Bitcoin-Price-Prediction)
(5-минутный ноутбук: признаки OHLCV, цель — направление следующего бара, XGBoost)
на свежие данные Bybit с хронологической walk-forward-валидацией.

> **Дисклеймер.** Сигналы — вывод статистической модели, а не гарантия дохода и не
> персональная финансовая рекомендация. Бот **не** размещает ордера, **не** использует
> приватные API, **не** запрашивает баланс и **не** требует ключей. Фактические позиции
> учитываются только после ручной регистрации.

> **📖 Полный гайд по использованию: [`docs/user_guide.md`](docs/user_guide.md)** —
> установка, настройка (включая горизонт прогноза и условия выхода), запуск TEST/LIVE,
> чтение дашборда, регистрация и сопровождение позиций, FAQ, решение проблем,
> ограничения модели. README ниже — краткая справка.

Требуется Python 3.10+ (проверено на 3.11 и 3.13). Из корня проекта:

## Быстрый старт (полный сценарий)

```powershell
# 1. Скачать историю BTCUSDT (публичный REST Bybit, ~2-3 мин)
python scripts\download_history.py

# 2. Обучить модель + walk-forward-валидация (офлайн, ~35 с)
python scripts\train_model.py

# 3. Демо без сети: реплей последних баров + дашборд
python scripts\run_bot.py --mode TEST --replay-bars 40 --speed 4

# 4. Живой мониторинг: публичный WebSocket Bybit (Ctrl+C для выхода)
python scripts\run_bot.py --mode LIVE

# 5. Ручной учёт позиций (офлайн)
python scripts\position_cli.py list
```

## Конфигурация — `config/default.yaml`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `mode` | `TEST` | `TEST` — офлайн-реплей; `LIVE` — публичный WS Bybit |
| `exchange.symbol/category/interval` | `BTCUSDT`/`spot`/`"5"` | инструмент настраивается; категория spot/linear/inverse |
| `model.horizon_bars` | `1` | **на сколько баров вперёд смотрит модель** (1 = 5 мин). Смена требует переобучения |
| `model.confidence_threshold` | `0.55` | ниже порога → HOLD (воздержание) |
| `model.feature_set` | `auto` | `raw` (как в оригинале) / `ratio` (стационарный) / `auto` (сравнить и выбрать) |
| `signals.stale_after_intervals` | `3` | порог устаревания данных (× интервал) |
| `positions.exit_rules.*` | `null` | **явные** TP/SL/max_hold; пока не заданы — рекомендация на вход воздерживается |
| `journal.path` | `data/journal/journal.json` | журнал сигналов и позиций |

Секреты в конфигурации не используются и не должны появляться.

## Данные (Этап 2a)

```powershell
python scripts\download_history.py [--start 2024-01-01] [--end 2026-06-30]
python scripts\manual_checks\check_stage2_data.py     # ожидание: RESULT: PASS (9)
```

Файлы: `data\raw\*.csv` + `*.metadata.json` (инструмент, категория, интервал, период,
дата загрузки), `data\processed\*.clean.csv` + `*.clean.report.json`. Дубликаты удаляются,
порядок строго по возрастанию времени, незакрытые свечи исключаются, пропуски (gaps)
детектируются и логируются, но **не заполняются** — данные не фабрикуются.

## Модель (Этап 2b)

```powershell
python scripts\train_model.py            # полная валидация + финальный артефакт
python scripts\train_model.py --quick    # быстрый смоук-прогон
python scripts\manual_checks\check_stage2_model.py   # ожидание: RESULT: PASS (6)
```

- Цель (как в оригинальном ноутбуке): `y = +1`, если close через `horizon_bars` баров выше,
  иначе `-1` (ничья → `-1`); XGBoost с параметрами по умолчанию + фиксированный seed.
- Walk-forward: expanding window, 8 окон, переобучение на каждом окне, **embargo**
  (в обучение попадают только строки, чья метка полностью известна до начала окна) —
  утечка будущих данных исключена.
- Сравнение: `raw` vs `ratio` vs majority/momentum baselines vs протокол оригинала
  (single split 75/25). Итоги на данных 2024-01-01→2026-10-21: `ratio` acc **0.5059**
  против majority 0.4981; acc при уверенности ≥0.55 — 0.5142 (покрытие 21.3%).
- Артефакт: `data\models\<model_version>\` — `model.joblib`, `model_card.json`
  (версия, инструмент, горизонт, признаки, метрики, версии библиотек, ограничения),
  `walk_forward.json`. Отчёт: `docs\validation_report.md`.
- Predictor отклоняет артефакт, если конфиг (symbol/interval/**horizon_bars**) не
  соответствует model card.

### Ограничения модели (честно)

- Превосходство над baseline статистически заметно (~5σ на 118k оконных прогнозов), но
  мало: ожидаемый валовой выигрыш ≈ **0.001% на сигнал** против ~0.2% комиссий
  round-trip — **для комиссионной торговли на 5-минутном горизонте недостаточно**.
- Accuracy ≠ прибыльность; спред/комиссии/слиппедж в метриках не учитываются.
- Исходная модель из репозитория невоспроизводима (нет данных и артефакта) — сравнение
  выполнено по протоколу. Метрики из README автора проверке не подлежат.
- Модель деградирует при смене рыночного режима; рекомендуется периодическое
  переобучение (`train_model.py`) вручную. Автопереобучение на результатах позиций
  намеренно не реализовано.

## Мониторинг и сигналы (Этап 3)

```powershell
python scripts\run_bot.py --mode LIVE                 # до Ctrl+C
python scripts\run_bot.py --mode LIVE --duration 660  # или фиксированная длительность
python scripts\run_bot.py --mode TEST --replay-bars 40 --speed 4   # офлайн-демо
python scripts\manual_checks\check_stage3_stream.py                # ожидание: RESULT: PASS (10)
python scripts\manual_checks\check_stage3_stream.py --live         # + read-only WS Bybit: PASS (11)
```

Дашборд показывает: цену (ticker), последние закрытые свечи и формирующуюся свечу,
состояние соединения, свежесть данных (FRESH/STALE), текущий сигнал (действие,
уверенность, время выдачи, время бара, цена, версия модели, горизонт), историю
сигналов, открытые позиции и рекомендацию советника.

Правила: сигнал — только после закрытия свечи (`confirm=true`); ping каждые 20 с;
reconnect с backoff 1→60 с и REST-догрузкой пропущенных баров; при устаревших/неполных
данных новый сигнал помечается **не актуальным** (`data_fresh=false`) с перечислением
причин; seed истории при старте сигналы не порождает.

## Позиции и сопровождение (Этап 4)

Журнал `data\journal\journal.json` хранит историю всех сигналов и ручные позиции
(переживает перезапуск; в TEST-реплее по умолчанию используется отдельный
`journal_test.json`, чтобы демо-сигналы не смешивались с боевой историей).

```powershell
# сигналы (модель) и позиции (факты пользователя) РАЗДЕЛЕНЫ:
python scripts\position_cli.py signals --last 20

# зарегистрировать фактический вход (опционально привязав к сигналу и задав условия выхода)
python scripts\position_cli.py register-entry --price 84500 --quantity 0.01 --signal-id sig-000123 --tp 1.5 --sl 1.0 --max-hold 12 --time "2026-10-22 10:15"

# частичное закрытие
python scripts\position_cli.py close --position-id pos-000001 --price 85000 --quantity 0.004

# полное закрытие (остаток)
python scripts\position_cli.py close --position-id pos-000001 --price 84800

python scripts\position_cli.py list --all
python scripts\position_cli.py show --position-id pos-000001
python scripts\position_cli.py stats
python scripts\position_cli.py events --last 20
python scripts\manual_checks\check_stage4_positions.py   # ожидание: RESULT: PASS (11)
```

Семантика и правила сопровождения:

- Сигнал **не считается исполненным**, пока вход не зарегистрирован вручную
  (`register-entry`); регистрация с `--signal-id` связывает позицию с сигналом и
  фиксирует: время сигнала, цену, горизонт прогноза, версию модели, условия выхода.
- Для **spot BTCUSDT SELL = закрыть/уменьшить подтверждённую длинную позицию**.
  Шорты не поддерживаются (регистрация SHORT отклоняется).
- Пока позиция открыта, каждый новый свежий сигнал сначала оценивает ЕЁ:
  **ДЕРЖАТЬ / РАССМОТРЕТЬ ЗАКРЫТИЕ / НАБЛЮДАТЬ**. Встречный сигнал сопровождается
  объяснением причины и списком сработавших настроенных условий выхода.
- Условия выхода — только явно заданные (`positions.exit_rules` в конфиге или
  `--tp/--sl/--max-hold` при регистрации). Уровни стоп-лоссов/целей/сроков **не
  изобретаются**; пока правила не заданы, рекомендация на вход воздерживается.
- Если открытых позиций нет, а модель дала SELL: бот сообщает, что **фактическое
  состояние портфеля неизвестно**, и не утверждает, что нужно что-то закрывать.
- При устаревших данных рекомендации по управлению позицией не выдаются.
- Журнал фиксирует: сигналы с ценой на момент выдачи, подтверждения входа/выхода,
  причины смены статуса и результат позиции (PnL по ручным данным). Правила сигналов
  не меняются и модель на результатах позиций автоматически не переобучается.

## Режимы и безопасность

- **TEST**: офлайн-реплей сохранённых данных + демонстрационные сценарии (включая STALE);
  ручные проверки этапов по умолчанию офлайн; read-only проверки публичного Bybit —
  отдельными флагами (`--live`).
- **LIVE**: публичные WS/REST Bybit, отображение сигналов, сопровождение вручную
  зарегистрированных позиций.
- Размещение/изменение/отмена ордеров, приватные API, балансы и ключи **отсутствуют**;
  структурный скан кода на их отсутствие входит в ручные проверки (A9/A11).
- Компоненты Finam/MOEX в проекте отсутствуют (workspace был пуст; удалять было нечего).

  portfolio/              # journal (сигналы+позиции), advisor (сопровождение)

  bot.py                  # оркестратор TEST (реплей) / LIVE (WS)

подключить другую биржу без изменения остального кода.

## Решение проблем

- **UserWarning XGBoost о pickle при загрузке модели**: артефакт сохранён другой версией
  XGBoost. Безвредно; устраняется локальным переобучением `python scripts\train_model.py`.
- **Кадры дашборда при копировании из терминала**: в Windows Terminal очистка экрана
  сдвигает старые кадры в scrollback — на экране это одна панель. При проблемах с ANSI:
  `--line-ui` (или `NO_ANSI=1`).
- **403 от Bybit**: превышен IP-лимит (600 запросов/5 с) — подождите ~10 минут;
  загрузчик истории троттлит запросы автоматически.
- **Журнал повреждён**: бот не перезаписывает его молча — восстановите файл вручную
  (события и позиции хранятся в `data\journal\journal.json`).
